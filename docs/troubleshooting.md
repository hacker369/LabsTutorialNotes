# 实验环境故障排查

排错时先确认环境和观察结果，再根据证据定位问题。避免一次修改多个配置，否则很难判断真正原因。

## 通用排查顺序

1. **确认目标和入口**：访问 URL、端口、路径、请求方法和参数是否正确。
2. **确认服务状态**：Web 服务、运行时和数据库是否正常启动。
3. **确认版本兼容性**：核对 PHP、数据库、Apache/Nginx、操作系统和靶场版本。
4. **确认配置和权限**：检查数据库连接配置、扩展加载、目录权限和虚拟主机根目录。
5. **查看日志**：优先阅读 Web 服务、PHP 和数据库日志中的首个相关错误。
6. **缩小复现范围**：用最小请求或基础关卡验证，再恢复完整操作。
7. **记录结果**：写清现象、证据、根因、改动和验证结果。

## 常见问题

| 现象 | 优先检查 |
|---|---|
| 页面无法打开 | 服务是否启动、端口冲突、虚拟主机、路径和防火墙规则 |
| 数据库连接失败 | 主机、端口、账号、密码、库名、认证方式和数据库日志 |
| 出现 undefined function mysql_connect() | 旧版 mysql_* API 与当前 PHP 版本不兼容；核对靶场版本和运行时要求 |
| 关卡行为与教程不一致 | 源码分支、PHP/数据库版本、请求方法、字符集、代理工具和服务配置 |
| 上传实验未按预期运行 | 实际请求内容、服务端文件名、上传目录、解析配置和文件权限 |
| 图片不显示 | Markdown 相对路径、大小写、文件是否存在，以及 Docsify 的路由基准 |
| 侧栏链接打不开 | 文件路径、扩展名大小写、URL 编码和 Docsify 路由格式 |

## 报告一个可复现的问题

建议附上：

- 靶场名称、版本或提交号。
- 操作系统、PHP、数据库和 Web 服务版本。
- 访问路径、请求方法及脱敏后的关键请求。
- 完整错误信息或日志片段。
- 预期行为与实际行为。
- 已经尝试过的排查步骤。

不要在 Issue 或笔记中提交真实密码、访问令牌或未授权目标的敏感信息。
