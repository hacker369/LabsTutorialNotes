# 仓库维护说明

本文记录 LabsTutorialNotes 的目录组织、内容质量与发布检查流程，方便作者和协作者持续维护。

## 当前结构

- 根目录的四篇 Markdown 文件是现有完整靶场笔记；在迁移期间继续保留，避免一次性移动内容造成图片与章节锚点失效。
- `notes/<lab>/README.md` 是新的靶场导航入口。
- `docs/` 存放共用的环境指南、故障排查、笔记模板和术语表。
- `img/` 暂时保留既有截图路径；迁移图片前必须先检查所有引用。
- `scripts/check_images.py` 与 GitHub Actions 用于检查图片引用和文件体积。

## 内容质量标准

每篇新增或重构的实验笔记应尽量包含：

1. 靶场来源、关卡、核心考点与验证状态。
2. 实际测试环境及关键版本。
3. 必要的源码位置与数据流分析。
4. 请求、响应和观察结果。
5. 可复现步骤、原理解释和排错记录。
6. 根因对应的修复建议及验证方法。
7. 有用的参考资料。

未在记录环境中复现的内容应标为“待验证”，不能仅凭网上教程或已有截图声称当前版本验证成功。

## 文件与图片约定

- 新文件优先放入对应的 `notes/<lab>/` 目录。
- 共用的环境与排错内容放入 `docs/`，避免在多篇教程中重复维护。
- 代码块语言标记应与内容匹配，例如 `bash`、`sql`、`http`、`html`、`text`。
- 图片应有说明文字；优先保留能解释关键行为的截图，避免重复截图。
- 新增图片前先压缩；请勿批量覆盖或删除现有图片而不备份。
- 在重命名或移动图片前，先搜索全部 Markdown 引用，并在迁移后运行检查脚本。
- 当前仓库未启用 Git LFS；不要在没有评估历史体积、Pages 兼容性与协作影响前，直接切换图片存储策略。

## 推荐的迁移流程

1. 在独立分支中修改，避免未经检查的内容直接进入主分支。
2. 先创建靶场索引，再逐段拆分原始长笔记。
3. 每次迁移后检查标题层级、代码块、相对链接、图片引用与 Docsify 路由。
4. 更新 README、英文首页、`home.md`、`_sidebar.md` 和 `_navbar.md`。
5. 运行 `python3 scripts/check_images.py --summary`；如环境允许，也运行 CI 中的图片检查和 Markdown 链接检查。
6. 人工打开站点与 GitHub 文件，确认关键链接和图片正常。

## 建议的后续拆分

SQLi-Labs 是当前篇幅最大的主笔记，可先按关卡范围拆分；XSS-Labs、Upload-Labs 和 Google XSS Game 再按相近规模拆分。拆分时应保留原始笔记，直到所有关卡内容、图片和链接完成验证。

## 安全与隐私

- 只记录本地或明确授权环境中的实验。
- 不提交真实密码、访问令牌或其他敏感信息。
- 不把关闭宿主机安全防护作为默认实验步骤；优先使用隔离环境。
- 不将可用于未授权目标的自动化攻击流程作为项目目标。
